# 4.2 Перечисления

Перечисления (`enum`) позволяют создавать типы с заранее определённым набором именованных значений. Они полезны, когда программа должна различать несколько состояний, режимов или категорий.

Представим программу, которая выполняет задачи. Каждая задача может ожидать запуска, выполняться или быть завершённой. Эти состояния можно было бы обозначить числами, но по значению `1` трудно понять, что именно оно означает. Перечисление позволяет дать каждому состоянию понятное имя.

## Объявление перечисления

Для объявления перечисления используют ключевое слово `enum`. За ним указывают имя нового типа, а внутри фигурных скобок перечисляют варианты:

```cvolo
enum TaskState
{
    Pending,
    Running,
    Completed
}
```

`TaskState` - имя объявленного типа. В нём определены три варианта:

- `Pending` - задача ожидает запуска;
- `Running` - задача выполняется;
- `Completed` - задача завершена.

Значение обычного перечисления обозначает **только один из объявленных вариантов**. Варианты не имеют собственных полей: каждый представляет собой именованное значение, которому соответствует целочисленный код.

Если при объявлении перечисления не задавать числовые значения вариантов, компилятор присвоит их автоматически, начиная с `0`:

| Вариант | Числовое значение |
| --- | ---: |
| `TaskState.Pending` | `0` |
| `TaskState.Running` | `1` |
| `TaskState.Completed` | `2` |

> **Важно:** Перечисление должно содержать хотя бы один вариант. Имена вариантов внутри одного объявления не должны повторяться.

## Использование перечисления

Для обращения к варианту указывают имя перечисления, точку и имя нужного варианта - например, `TaskState.Pending`.

Создадим переменную `state`, которая будет хранить состояние задачи. Поскольку состояние может меняться, объявим переменную через `var`:

```cvolo tab="С выводом типа"
var state = TaskState.Pending;

state = TaskState.Running;
state = TaskState.Completed;
```

```cvolo tab="С указанием типа"
var TaskState state = TaskState.Pending;

state = TaskState.Running;
state = TaskState.Completed;
```

В первом варианте компилятор определяет тип переменной по значению `TaskState.Pending`. Во втором тип `TaskState` указан явно. Обе записи равнозначны, а `var` разрешает присваивать переменной новое значение.

Текущее состояние задачи можно проверить с помощью условия:

```cvolo
if (state == TaskState.Completed)
{
    // Задача завершена.
}
```

Несмотря на то что варианты представлены числами, `TaskState` остаётся отдельным типом. Например, прямое присваивание целого числа недопустимо:

```cvolo
TaskState state = 1; // Ошибка: int нельзя неявно преобразовать в TaskState.
```

Это **не означает, что преобразования запрещены вообще**. Для них в Cvolo предусмотрено явное приведение типов, которое рассмотрим ниже.

## Числовые значения и тип хранения

Числовые значения вариантов можно задать самостоятельно. Например, если состояния должны соответствовать кодам внешней системы:

```cvolo
enum TaskState : byte
{
    Pending = 1,
    Running = 5,
    Completed
}
```

Если очередному варианту число не задано, он получает значение на единицу больше предыдущего. Поэтому здесь `Completed` будет соответствовать числу `6`.

Запись `: byte` определяет тип, используемый для хранения числовых кодов. Если его не указать, используется `int`. Поддерживаются `int`, `uint`, `short`, `ushort`, `long`, `ulong`, `char`, `byte` и `sbyte`.

Явно заданные значения должны быть известны во время компиляции. Допускаются целочисленные константы и поддерживаемые выражения над ранее объявленными вариантами.

Значение перечисления можно явно преобразовать в число:

```cvolo
int code = (int)TaskState.Running;
```

Число также можно явно преобразовать в перечисление, но не всякое число соответствует объявленному варианту. Поэтому в безопасном коде компилятор сравнивает число со значениями вариантов: если совпадение найдено, результат содержит соответствующий вариант, а если нет - сообщает об отсутствии значения. Например, для объявления выше число `5` соответствует `TaskState.Running`, а `10` не соответствует ни одному варианту.

Результат выражения `(TaskState)code` имеет тип `Option<TaskState>`: при совпадении это `Some`, при отсутствии совпадения - `None`. Подробно `Option<T>` рассматривается в будущей [статье об `Option<T>`](../06-optional-values/6-1-option.md).

## Использование в `switch`

Когда для разных состояний нужно выполнять разные действия, удобно использовать `switch`:

```cvolo
using System;

void PrintState(TaskState state)
{
    switch (state)
    {
        case Pending:
            Console.WriteLine("Ожидает запуска");
        case Running:
            Console.WriteLine("Выполняется");
        case Completed:
            Console.WriteLine("Завершена");
    }
}
```

Внутри `switch` варианты записываются без `TaskState.`, потому что компилятору уже известен тип проверяемого значения. Выполняется только выбранная ветвь: **автоматического перехода к следующему `case` нет**, поэтому завершать каждую ветвь инструкцией `break` не требуется.

Для обычного перечисления компилятор проверяет, что `switch` обрабатывает все варианты. Если нужно предусмотреть общий случай, можно использовать `default` или `case _`:

```cvolo
switch (state)
{
    case Pending:
        // Ожидание запуска.
    default:
        // Все остальные состояния.
}
```

Обе формы обозначают запасную ветвь. Она также позволяет не перечислять каждый вариант отдельно.

Подробнее о конструкции `switch` можно прочитать в [разделе 3.4 «Конструкция `switch`»](../03-control-flow/3-4-switch.md).

## Сведения о перечислении

Компилятор предоставляет несколько встроенных способов получить сведения о перечислении. Например:

```cvolo
enum Level : byte
{
    Easy = 1,
    Normal = 2,
    Hard = 4
}
```

Для значения перечисления доступен метод `Name()`, который возвращает имя текущего варианта. Через имя типа можно получить и другие сведения: `Count` (число вариантов), `Min` и `Max` (минимальное и максимальное числовые значения), а также `Values` (доступный только для чтения срез значений).

Выберите вкладку, чтобы посмотреть использование каждой возможности и результат вывода в консоль. Во всех примерах используется объявленный выше тип `Level`.

```cvolo tab="Имя варианта"
using System;

int main()
{
    Level level = Level.Normal;
    Console.WriteLine(level.Name());
    return 0;
}
```

```output
Normal
```

```cvolo tab="Count, Min и Max"
using System;

int main()
{
    Console.WriteLine(Level.Count);
    Console.WriteLine(Level.Min);
    Console.WriteLine(Level.Max);
    return 0;
}
```

```output
3
1
4
```

```cvolo tab="Values"
using System;

int main()
{
    for (int i = 0; i < Level.Values.Length; i = i + 1)
    {
        Level current = Level.Values[i];
        Console.WriteLine(current.Name());
    }

    return 0;
}
```

```output
Easy
Normal
Hard
```

Все эти возможности предоставляются компилятором: объявлять `Name()`, `Count`, `Min`, `Max` и `Values` самостоятельно не требуется.

## Перечисления флагов

Иногда нужно хранить **несколько независимых признаков одновременно**. Например, пользователь может иметь право и на чтение, и на запись. Обычное перечисление выбирает один вариант, а для сочетания признаков предназначен атрибут `[Flags]`:

```cvolo
[Flags]
enum Permissions : byte
{
    None,
    Read,
    Write,
    Execute
}
```

Атрибут изменяет правила автоматического назначения числовых значений:

- `None` - `0`, пустой набор признаков;
- `Read` - `1`, первый бит;
- `Write` - `2`, второй бит;
- `Execute` - `4`, третий бит.

Каждый ненулевой признак занимает отдельный бит, поэтому их можно объединять оператором `|` и проверять методом `HasFlag()`.

```cvolo tab="С выводом типов"
val access = Permissions.Read | Permissions.Write;
val canWrite = access.HasFlag(Permissions.Write);
```

```cvolo tab="С указанием типов"
Permissions access = Permissions.Read | Permissions.Write;
bool canWrite = access.HasFlag(Permissions.Write);
```

В обоих примерах `canWrite` равно `true`: переменная `access` содержит флаг `Write`. Также поддерживаются операции `&`, `^` и `~`; последняя ограничивается маской объявленных отдельных признаков.

Для `[Flags]` действуют дополнительные правила:

- Тип хранения должен быть беззнаковым: `uint`, `ushort`, `ulong`, `byte` или `char`.
- Если объявлен вариант со значением `0`, его имя должно быть `None`, `Empty`, `Unset` или `Zero`. Объявлять нулевой вариант необязательно.
- `Count` и `Values` учитывают только отдельные ненулевые флаги, без нулевого и составных вариантов.

Полный набор вариантов в `switch` для `[Flags]` не требуется, поскольку признаки могут образовывать сочетания. Но если при выполнении не найдётся подходящая ветвь и нет `default`, программа аварийно завершится. Поэтому запасная ветвь здесь особенно полезна.

Общие правила применения атрибутов будут рассмотрены в отдельной [статье 4.16 «Атрибуты»](4-16-attributes.md).

## Перечисления с `[NonExhaustive]`

Представим, что в одном файле объявлено перечисление, которое используется в других файлах проекта. Позже в него могут добавить новый вариант. Если код, использующий перечисление, предполагает, что других вариантов никогда не будет, такое изменение потребует пересмотра соответствующих `switch`.

Атрибут `[NonExhaustive]` заранее предупреждает об этом и заставляет код из других файлов предусмотреть запасную ветвь.

```cvolo tab="TaskState.cvl"
[NonExhaustive]
enum TaskState
{
    Pending,
    Running,
    Completed
}
```

```cvolo tab="Main.cvl"
using System;

void PrintState(TaskState state)
{
    switch (state)
    {
        case Pending:
            Console.WriteLine("Ожидает запуска");
        case Running:
            Console.WriteLine("Выполняется");
        case Completed:
            Console.WriteLine("Завершена");
        default:
            Console.WriteLine("Неизвестное состояние");
    }
}
```

Здесь все три известных состояния уже перечислены, но `default` **всё равно обязателен**: `TaskState` объявлен в другом файле и помечен `[NonExhaustive]`. Например, в будущей версии к нему может добавиться вариант `Cancelled`, и запасная ветвь уже будет предусмотрена.

В файле, где объявлено само перечисление, действует обычная проверка полноты `switch`: достаточно обработать все известные варианты или добавить `default`.

Важно: атрибут **не позволяет добавлять варианты к перечислению из другого файла**. Он только меняет требования компилятора к обработке этого перечисления. В текущей версии Cvolo проверка различает именно файлы (единицы компиляции), а не границы пакетов.
