# 4.4 Композиция типов

Мы уже знаем, как объявлять структуры (`struct`), перечисления (`enum`) и объединения (`union`). Эти типы можно использовать не только по отдельности, но и **как части других типов**. Такой способ организации данных называют **композицией**.

Например, структура может содержать другую структуру в качестве поля, а один из вариантов объединения - хранить экземпляр структуры. Это позволяет описывать более сложные данные, используя уже знакомые типы.

## Структура внутри другой структуры

Представим, что нужно описать отрезок на плоскости. У него есть две точки: начало и конец. Координаты точки мы уже умеем хранить в структуре `Point` из [раздела 4.1 «Структуры»](4-1-structures.md).

```cvolo
struct Point
{
    int X;
    int Y;
}

struct Segment
{
    Point Start;
    Point End;
}
```

В `Segment` объявлены два поля:

- `Start` - начальная точка типа `Point`;
- `End` - конечная точка того же типа.

Объявлять координаты `X` и `Y` повторно не требуется: они уже описаны внутри `Point`. У каждого экземпляра `Segment` будут собственные начальная и конечная точки.

### Создание экземпляра с вложенными значениями

При создании `Segment` зададим значения обоих полей. Поскольку поля `Start` и `End` имеют тип `Point`, их можно инициализировать без повторного указания имени типа. Сначала покажем рекомендуемую короткую запись, затем полную:

```cvolo tab="Сокращённая запись"
var segment = Segment
{
    Start = (X: 10, Y: 20),
    End = (X: 30, Y: 40)
};
```

```cvolo tab="Полная запись"
var segment = Segment
{
    Start = Point
    {
        X = 10,
        Y = 20
    },
    End = Point
    {
        X = 30,
        Y = 40
    }
};
```

Оба варианта создают одинаковый экземпляр `Segment`. В основной, сокращённой записи компилятор определяет `Point` по типам полей `Start` и `End`. Во второй вкладке тип указан явно для сравнения. **Внутри круглых скобок используют `:`, а не `=`.**

Чтобы обратиться к координате вложенной структуры, используют последовательность имён полей через точку:

```cvolo
int x = segment.Start.X; // 10
int y = segment.End.Y;   // 40
```

Здесь `segment.Start` - поле типа `Point`, а `.X` обращается к его координате `X`.

Поскольку `segment` объявлен с `var`, его вложенные поля тоже можно изменять:

```cvolo
segment.Start.X = 15;
```

Теперь координата `X` начальной точки равна `15`. Подробные правила изменяемости мы уже рассматривали в статье о структурах; передачу и копирование составных значений изучим отдельно.

## Перечисления и объединения как поля структуры

Поле структуры может иметь тип `enum` или `union`. Например, мы можем описать ячейку таблицы, у которой есть положение, содержимое и оформление.

```cvolo
enum CellStyle
{
    Normal,
    Highlighted
}

union CellValue
{
    int Number;
    string Text;
    void Empty;
}

struct Cell
{
    Point Position;
    CellValue Content;
    CellStyle Style;
}
```

В структуре `Cell` три поля разных пользовательских типов:

- `Position` хранит положение ячейки с помощью `Point`;
- `Content` хранит один из вариантов объединения `CellValue`;
- `Style` хранит значение перечисления `CellStyle`.

Создадим экземпляр `Cell`. Для поля `Position` используем сокращённую запись, поскольку его тип `Point` уже известен. Вариант `union` в поле `Content` инициализируем явно. Во второй вкладке покажем полную запись:

```cvolo tab="Сокращённая запись"
var cell = Cell
{
    Position = (X: 2, Y: 3),
    Content = CellValue
    {
        Text = "Привет"
    },
    Style = CellStyle.Highlighted
};
```

```cvolo tab="Полная запись"
var cell = Cell
{
    Position = Point
    {
        X = 2,
        Y = 3
    },
    Content = CellValue
    {
        Text = "Привет"
    },
    Style = CellStyle.Highlighted
};
```

В сокращённой записи компилятор определяет `Point` по полю `Position`. Для `Content` используется явная запись `CellValue { Text = "Привет" }`: сокращённая инициализация варианта `union` в круглых скобках в текущей версии ещё не поддерживается.

В обоих примерах у структуры `Cell` **есть все три поля одновременно**, но в поле `Content` активен только один вариант объединения - `Text`.

Правила работы вложенных типов не меняются: к координатам обращаются через точку, значение перечисления сравнивают с его вариантами, а содержимое объединения проверяют через `is` или `switch`.

Подробнее о вариантах рассказано в [разделе 4.2 «Перечисления»](4-2-enum.md) и [разделе 4.3 «Объединения»](4-3-union.md).

## Структура внутри варианта объединения

Композиция работает и в обратную сторону: вариант `union` может содержать структуру.

Например, положение объекта можно указать либо координатами, либо номером точки в заранее известном списке:

```cvolo
union Location
{
    Point Coordinates;
    int Index;
}
```

Создадим значение с вариантом `Coordinates`. Тип содержимого варианта известен из объявления `Location`, поэтому здесь тоже можно использовать короткую запись:

```cvolo tab="Сокращённая запись"
var location = Location
{
    Coordinates = (X: 5, Y: 10)
};
```

```cvolo tab="Полная запись"
var location = Location
{
    Coordinates = Point
    {
        X = 5,
        Y = 10
    }
};
```

Чтобы получить координаты, сначала проверим активный вариант:

```cvolo
if (location is Coordinates point)
{
    int x = point.X;
    int y = point.Y;
}
```

Внутри блока `point` имеет тип `Point`, поэтому его поля доступны обычным способом. Если активен `Index`, условие не выполнится. Сам список точек находится вне `Location`: объединение хранит только номер выбранной точки, а не массив.

> **Важно:** Для композиции не нужно объявлять один тип внутри другого. Обычно каждый тип описывают отдельно и используют как часть другого, когда он представляет самостоятельную часть данных. Например, `Point` один раз описывает координаты, а `Segment` и `Cell` хранят точки в своих полях вместо повторного объявления `X` и `Y`.
