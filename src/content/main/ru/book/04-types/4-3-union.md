# 4.3 Объединения

Объединения (`union`) позволяют создавать типы, экземпляры которых могут содержать **один из нескольких вариантов данных**. В отличие от структуры, у которой одновременно существуют все объявленные поля, у объединения в каждый момент активен только один вариант.

Представим программу, которая работает с таблицей. В одной ячейке может находиться число, в другой - текст, а третья может быть пустой. Нам нужен тип для **содержимого ячейки**, который позволяет хранить любое из этих значений и понимать, какое именно значение сейчас записано. Для этого хорошо подходит `union`.

## Объявление объединения

Для объявления объединения используют ключевое слово `union`. За ним указывают имя нового типа, а внутри фигурных скобок перечисляют варианты:

```cvolo
union CellValue
{
    int Number;
    string Text;
    void Empty;
}
```

`CellValue` - имя объявленного типа. В нём определены три варианта:

- `Number` - хранит целое число типа `int`;
- `Text` - хранит строку типа `string`;
- `Empty` - обозначает пустую ячейку и не содержит данных.

Каждый вариант объявляют **в формате `Тип Имя;`**, как поле структуры. Но есть существенное отличие: поля `struct` существуют одновременно, а экземпляр `union` содержит данные только одного активного варианта.

Для варианта, которому не требуется хранить значение, указывают тип `void`. В нашем примере таким вариантом стал `Empty`. **Его имя не является специальным ключевым словом**, а наличие варианта без данных необязательно: объединение может состоять только из вариантов с данными.

## Создание экземпляра объединения

Создадим экземпляр `CellValue`, содержащий число:

```cvolo tab="С выводом типа"
var cell = CellValue
{
    Number = 42
};
```

```cvolo tab="С указанием типа"
var CellValue cell = CellValue
{
    Number = 42
};
```

В обоих случаях переменная `cell` имеет тип `CellValue`, а её активный вариант - `Number`. Запись `Number = 42` задаёт содержимое этого варианта. `var` позволяет позднее присвоить переменной новое значение.

Для другого содержимого выберем другой вариант:

```cvolo
CellValue text = CellValue
{
    Text = "Привет"
};

CellValue empty = CellValue
{
    Empty = void
};
```

В записи `Empty = void` выражение `void` означает, что выбранный вариант не содержит данных.

> **Важно:** При создании экземпляра `union` через фигурные скобки требуется указать **ровно один вариант**. Нельзя задать несколько вариантов сразу или оставить их все неуказанными.

Как и при инициализации структур, вместо `=` можно использовать `:`:

```cvolo
CellValue cell = CellValue
{
    Number: 42
};
```

> **Рекомендация:** Обе формы допустимы, но для единообразия в фигурных скобках предпочтительнее `=`.

## Проверка активного варианта

Чтобы обработать содержимое ячейки, сначала нужно определить, какой вариант активен. Для этого отлично подходит конструкция `switch`:

```cvolo
using System;

void PrintCell(CellValue cell)
{
    switch (cell)
    {
        case Number number:
            Console.WriteLine(number);

        case Text text:
            Console.WriteLine(text);

        case Empty:
            Console.WriteLine("Ячейка пуста");
    }
}
```

В этом примере:

- `case Number number:` выбирает вариант `Number` и делает его значение доступным под именем `number` с типом `int`;
- `case Text text:` выбирает вариант `Text` и предоставляет строку под именем `text`;
- `case Empty:` обрабатывает вариант без данных, поэтому дополнительная переменная не нужна.

Таким образом, `switch` проверяет активный вариант и позволяет использовать его содержимое. Как и в случае с `enum`, после выполнения выбранной ветви **нет автоматического перехода к следующему `case`**, поэтому `break` не требуется.

### Обязательно ли проверять все варианты?

**Нет, при работе с объединением не обязательно каждый раз рассматривать все его варианты.** Например, если нас интересуют только числовые ячейки, можно воспользоваться `if` и проверкой `is`:

```cvolo
if (cell is Number number)
{
    Console.WriteLine(number);
}
```

Блок выполняется, только когда активен вариант `Number`. При этом переменная `number` доступна внутри блока и содержит его значение. Остальные варианты просто не подходят под условие.

А вот для **`switch` без запасной ветви** действует отдельное правило: компилятор требует перечислить все варианты объединения. Если нужно обработать только часть вариантов, можно добавить `default`:

```cvolo
switch (cell)
{
    case Number number:
        Console.WriteLine(number);

    default:
        Console.WriteLine("Ячейка содержит не число");
}
```

В примерах будем использовать `default` для всех остальных вариантов: так назначение запасной ветви сразу понятно.

Подробнее об общей работе `switch` можно прочитать в [разделе 3.4 «Конструкция `switch`»](../03-control-flow/3-4-switch.md).

## Прямой доступ к данным варианта

В Cvolo данные варианта можно получить и через точку, как поле структуры:

```cvolo
CellValue cell = CellValue
{
    Number = 42
};

int number = cell.Number;
```

Здесь мы точно знаем, что активен `Number`, потому что именно с ним создали экземпляр.

Однако **прямой доступ через точку не проверяет активный вариант**. Компилятор проверяет только, что `Number` вообще объявлен в `CellValue`. Поэтому даже такая запись может пройти проверку типов:

```cvolo
CellValue cell = CellValue
{
    Text = "Привет"
};

int number = cell.Number; // Нельзя рассчитывать на корректное число.
```

У этого экземпляра активен `Text`, а не `Number`. Чтение `cell.Number` не выберет другой вариант: программа попытается прочитать его содержимое как `int`. Результат может оказаться бессмысленным; чтение неактивного варианта более сложного типа может привести и к сбою программы.

> **Важно:** Используйте прямой доступ только тогда, когда **точно знаете**, какой вариант активен. Если значение может содержать разные варианты, сначала проверяйте его через `is` или разбирайте через `switch`. Тогда содержимое будет извлечено из подходящего варианта, а остальные случаи не попадут в эту ветвь.

## Отличие от структур и перечислений

Мы познакомились с тремя способами описывать пользовательские типы:

| Конструкция | Что хранит экземпляр |
| --- | --- |
| `struct` | Все объявленные поля одновременно. |
| `enum` | Один именованный вариант, которому соответствует целочисленный код. |
| `union` | Один активный вариант, который может содержать данные определённого типа либо не содержать их. |

Например, координаты точки удобно объединять в `struct`. Состояние задачи (`Pending`, `Running`, `Completed`) подходит для `enum`. А содержимое ячейки таблицы, которое может быть числом, строкой или пустым, - для `union`.

Варианты объединения могут содержать не только встроенные типы (`int`, `string` и другие), но и пользовательские структуры и перечисления. Это позволяет сочетать разные способы организации данных.
