# 1.6 Локализация документации

Локализация в Cvolo Docs строится вокруг общей структуры страниц. Английская и русская версии одной страницы используют один и тот же относительный путь и slug, а переводится уже содержимое Markdown-файла: заголовки, объяснения и, при необходимости, текстовые данные примеров.

Поэтому при переключении языка достаточно заменить сегмент `en` ↔ `ru` в URL, сохранив остальную часть маршрута без изменений.

## Одинаковая структура файлов

Одна и та же страница должна находиться по одинаковому относительному пути в обеих локализациях:

```text mark-range="1:17:19|2:17:19"
src/content/main/en/book/01-introduction/1-1-hello-world.md
src/content/main/ru/book/01-introduction/1-1-hello-world.md
```

В примере различается только сегмент `en` ↔ `ru`; всё после него остаётся одинаковым.

Основа имени файла `1-1-hello-world` используется как slug страницы, но видимый заголовок от неё не зависит. В английском файле H1 может быть `# 1.1 Hello World`, а в русском - `# 1.1 Первая программа`.

Не создавайте отдельные имена вроде `1-1-pervaya-programma.md` только для RU. Это разрывает прямую связь между локализациями и усложняет переключение языка.

## Одинаковая структура chapter.toml

Совпадать должны не только файлы, но и порядок страниц.

Например, если английская глава содержит:

```toml
order = 1
pages = [
    "1-1-hello-world",
    "1-2-building-and-running"
]
```

то русский `chapter.toml` должен использовать те же имена файлов без `.md` и в том же порядке.

Видимые названия страниц берутся из H1 соответствующих Markdown-файлов, поэтому `chapter.toml` локализовать не нужно.

Поэтому английская и русская версии главы используют один и тот же порядок страниц, даже если их заголовки и содержимое редактируются независимо.

## Как это отражается в URL

Одинаковые относительные пути дают одинаковые маршруты после сегмента языка:

```text
/en/main/docs/book/01-introduction/1-1-hello-world/
/ru/main/docs/book/01-introduction/1-1-hello-world/
```

В этих адресах меняется только `en` ↔ `ru`. Версия `main`, раздел `book`, глава и slug страницы остаются теми же.

## Что именно переводить

Переводите то, что видит читатель: H1/H2/H3, абзацы, подписи и, при необходимости, текстовые данные примеров.

Имена API Cvolo, ключевые слова языка, реальные пути исходников и технические идентификаторы переводить не нужно. Например, `Console.WriteLine`, `Result<T, E>` и `libraries/Base/Result.cvl` должны оставаться одинаковыми, а объяснение их поведения пишется на языке страницы.

## Добавление новой страницы

При добавлении локализованной страницы удобно придерживаться одного порядка:

1. Создайте Markdown-файл в нужном относительном пути одной локализации.
2. Создайте такой же путь для второй локализации.
3. Добавьте одно и то же имя файла без `.md` в оба `chapter.toml`.
4. Напишите локализованный H1 и содержимое каждого файла.
5. Запустите `npm run docs:build` и `npm run docs:verify`.

Если полноценный перевод ещё не готов, лучше явно оставить задачу на перевод, чем придумывать другой путь или переносить страницу в случайное место. Структура документации должна оставаться общей.

## Проверка ссылок между страницами

Во внутренних ссылках также опирайтесь на общую логическую структуру документации, а не создавайте отдельную архитектуру для каждого языка.

Чем стабильнее slugs, тем проще поддерживать перекрёстные ссылки, search index и language switcher по мере роста документации.

Главный принцип локализации Cvolo Docs: **переводится содержание, но не идентичность страницы**.
