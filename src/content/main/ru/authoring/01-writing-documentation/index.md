# Как писать документацию Cvolo

Документация Cvolo устроена так, чтобы большую часть времени автор работал с обычными Markdown-файлами, а не с компонентами сайта.

Страница должна оставаться читаемой прямо на GitHub, но при сборке сайта Markdown получает дополнительные возможности: подсветку Cvolo-кода, объединённые блоки «код + вывод», вкладки, интерактивные деревья файлов, просмотр исходников и ручной Go To Definition.

Этот раздел описывает именно авторский workflow: как организовать контент, как оформлять примеры и когда использовать возможности рендера.

## С чего начинать

Если вы добавляете новую страницу, сначала определите, в какой раздел и главу она должна попасть.

Дальше всё зависит от задачи:

- для обычной статьи достаточно Markdown-файла с `# H1` и записи в `chapter.toml`;
- для примеров с выводом можно использовать `output`;
- для альтернативных вариантов — `tab`;
- для структуры проекта — `files`;
- для ссылок на исходники — `source` и `GoToDefinition`.

Специальные возможности рендера стоит использовать только там, где они действительно помогают объяснению. Они не заменяют текст: пример должен быть понятен и без знания внутреннего устройства сайта.

## Что описано дальше

Дальше последовательно разбираются:

- структура разделов, глав и страниц;
- кодовые блоки и вывод программы;
- вкладки;
- деревья файлов;
- ссылки на исходники;
- Go To Definition;
- локализация документации;
- сравнение изменений в коде;
- выделение строк и отдельных фрагментов кода.

После изменения контента полезно запускать:

```bash
npm run docs:build
npm run docs:verify
```

Первая команда пересобирает индекс документации, вторая проверяет маршруты и структуру контента. При обычной локальной разработке `npm run dev` запускает эти шаги автоматически перед Vite.
