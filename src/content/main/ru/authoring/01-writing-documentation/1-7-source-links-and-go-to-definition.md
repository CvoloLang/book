# 1.5 Source links и Go To Definition

Иногда документации недостаточно показать только публичное поведение типа или функции. Для Base SDK, `System`, compiler-known атрибутов и технических разделов полезно дать читателю быстрый путь к реальной реализации. Cvolo Docs поддерживает несколько уровней такой навигации: inline-ссылку на исходник, кнопку **Source** у целого блока кода и ручной Go To Definition для отдельных выражений внутри кода.

Все переходы к исходникам задаются явно автором статьи. Cvolo Docs не пытается автоматически определить, к какому файлу относятся `Result`, `Type`, `Console` или другие имена. Это сохраняет навигацию предсказуемой даже тогда, когда одинаковые имена встречаются в разных модулях.

## Inline-ссылка на исходник

Если в тексте упоминается конкретный файл, используйте обычную Markdown-ссылку с префиксом `source:` в адресе:

```markdown
[`Result.cvl`](source:libraries/Base/Result.cvl)
```

В веб-интерфейсе документации такая ссылка открывает встроенный source viewer:

[`Result.cvl`](source:libraries/Base/Result.cvl)

У ссылки остаётся GitHub fallback, поэтому она продолжает работать и без клиентского JavaScript.

Используйте inline source link, когда предложение говорит именно о файле или реализации. Не стоит превращать каждый термин статьи в ссылку: слишком много интерактивных элементов мешают чтению.

Путь после `source:` считается относительно compiler-репозитория, указанного как `compiler` в `config/book.toml`.

## Source у блока кода

Если весь пример относится к одному исходному файлу, добавьте атрибут `source="..."` после языка блока кода:

````markdown
```cvolo source="libraries/Base/Result.cvl"
public union Result<T, E> {
    T Ok;
    E Err;
}
```
````

В toolbar рядом с Copy появится кнопка **Source**:

```cvolo source="libraries/Base/Result.cvl"
public union Result<T, E> {
    T Ok;
    E Err;
}
```

Этот вариант подходит для фрагментов, где весь блок связан с одним файлом. Читатель видит короткий пример в статье, а при необходимости открывает полную реализацию.

Атрибут `source` не синхронизирует содержимое блока кода с файлом в GitHub. Он только задаёт ссылку на исходник, поэтому за актуальность показанного фрагмента по-прежнему отвечает автор статьи.

## Ручной Go To Definition

Go To Definition решает другую задачу: связывает **конкретное выражение внутри блока кода** с исходным файлом и позволяет перейти к его определению прямо из примера.

В обычном состоянии выражение остаётся частью подсвеченного кода. Интерактивность появляется только при наведении, поэтому пример не превращается в набор постоянно подчёркнутых ссылок.

Это удобно для выражений вроде `[Result]`, `Result`, `Option`, `Console` и других API, реализацию которых читатель может захотеть открыть прямо из примера.

### Глобальные правила проекта

Общие определения задаются в `config/go-to-definition.html`:

```html
<GoToDefinition Global="True">
  <Expression Source="libraries/Base/Result.cvl" Value="Result" />
  <Expression Source="libraries/Base/Attributes/ResultAttribute.cvl" Value="[Result]" />
</GoToDefinition>
```

Элемент `<GoToDefinition>` объединяет одно или несколько правил `<Expression>`. Каждое правило связывает значение `Value` с файлом из `Source`.

Правила из `config/go-to-definition.html` действуют для всех страниц проекта. Атрибут `Global="True"` в этом файле можно сохранять для единообразия формата, но сам файл уже задаёт глобальные правила.

Не добавляйте сюда каждый возможный символ языка. Глобальный набор лучше держать небольшим: только стабильные и однозначные выражения, которые регулярно встречаются в документации.

## Правила для одной страницы

Если связь нужна только в одной статье, директиву можно записать непосредственно в Markdown-файле:

```html
<GoToDefinition Global="True">
  <Expression Source="libraries/System/Console.cvl" Value="Console" />
</GoToDefinition>
```

Сборщик использует её как метаданные, поэтому сама директива в статье не отображается.

Если указать `Global="True"`, правила из этой директивы действуют на все блоки кода текущего Markdown-файла независимо от положения самой директивы. Такой вариант удобен, когда страница целиком посвящена одному API и одно выражение повторяется в нескольких примерах.

## Правило только для следующего блока кода

Если указать `Global="False"`, правила из директивы применяются только к следующему fenced-блоку кода. Это подходит для неоднозначного имени или локального примера, где связь не должна влиять на остальные блоки страницы.

Например:

````markdown
<GoToDefinition Global="False">
  <Expression Source="libraries/Base/Result.cvl" Value="Result" />
</GoToDefinition>

```cvolo
Result<int, ParseError> Parse(string text) {
    // ...
}
```
````

На странице сама директива не показывается. Перед следующим примером можно сразу подсказать читателю, что `Result` поддерживает переход к определению:

Наведите курсор на `Result`, чтобы открыть переход к исходнику.

<GoToDefinition Global="False">
  <Expression Source="libraries/Base/Result.cvl" Value="Result" />
</GoToDefinition>

```cvolo
Result<int, ParseError> Parse(string text) {
    // ...
}
```

## Как выбирается выражение

Сопоставление case-sensitive: `Result` и `result` - разные значения.

Для выражений, начинающихся или заканчивающихся идентификаторным символом, учитываются границы идентификатора. Поэтому правило `Result` не должно случайно превращать часть `LoadResult` в ссылку.

Если правила пересекаются, более специфичное выражение имеет приоритет. Например, при наличии правил для `Result` и `[Result]` внутри `[Result]` выбирается полный атрибут.

Поэтому в `Value` лучше указывать тот фрагмент, который читатель должен воспринимать как одну semantic reference.

## Отключение глобальных правил

Если глобальное правило создаёт неверную семантику в конкретной статье, добавьте в начало Markdown-файла:

```html
<DisableGlobalGoToDefinition />
```

Эта директива отключает для страницы правила из `config/go-to-definition.html`. Локальные `<GoToDefinition>` внутри той же страницы при этом продолжают работать.

Такой вариант полезен в advanced-разделах, где знакомое имя обозначает внутренний compiler type, а не публичный SDK symbol.

Выбирайте самый простой уровень навигации, который решает задачу: inline `source:` для ссылки в тексте, `source="..."` для целого блока и Go To Definition только тогда, когда переход по конкретному выражению действительно помогает читать код.
