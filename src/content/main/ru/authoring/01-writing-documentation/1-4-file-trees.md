# 1.4 Деревья файлов

Когда статья объясняет устройство репозитория или расположение библиотек, обычный `text`-блок технически подходит, но плохо передаёт иерархию. Для таких примеров используйте fenced-блок с идентификатором `files`: Cvolo Docs отобразит его как интерактивное дерево с иконками файлов и папок, а директории можно будет раскрывать и сворачивать.

Исходный Markdown при этом остаётся обычным читаемым Markdown. Папка обозначается завершающим `/`, а вложенность задаётся ветками `├──` / `└──` и отступами.

## Обычное дерево

Укажите `files` после открывающих обратных кавычек:

````markdown
```files
libraries/System/
├── Console.cvl
├── Environment.cvl
├── IO/
├── Math/
└── Threading/
```
````

В веб-интерфейсе документации этот блок отображается как интерактивное дерево:

```files
libraries/System/
├── Console.cvl
├── Environment.cvl
├── IO/
├── Math/
└── Threading/
```

Используйте дерево, когда сама иерархия важна для объяснения. Если нужно просто упомянуть один путь, inline-code вроде `libraries/System/Console.cvl` будет проще.

Поддерживаются алиасы `file`, `filetree` и `tree`, но в новой документации лучше последовательно использовать `files`.

## Дерево с переходом к исходникам

Файлы в дереве можно связать с реальными файлами в GitHub и открывать их во встроенном source viewer. Для этого в открывающем fence укажите `github`, а если нужна конкретная ветка, tag или commit — добавьте `ref`.

Например:

````markdown
```files github="IgorShaposhnikov/Cvolo" ref="master"
libraries/
├── Base/
│   ├── Option.cvl
│   └── Result.cvl
└── System/
    └── Console.cvl
```
````

В веб-интерфейсе документации папки по-прежнему раскрываются и сворачиваются, а файлы становятся переходами к исходникам:

```files github="IgorShaposhnikov/Cvolo" ref="master"
libraries/
├── Base/
│   ├── Option.cvl
│   └── Result.cvl
└── System/
    └── Console.cvl
```

Атрибут `github` указывается в форме `owner/repository`.

Атрибут `ref` может указывать не только на ветку, но и на tag или конкретный commit. Например, `ref="master"` использует ветку `master`, а `ref="v0.5.0"` может использовать release tag.

Если `ref` не указан, используется `main`, поэтому для репозитория Cvolo с веткой `master` его лучше задавать явно.

## Параметр root

Иногда в статье нужно показать только небольшой фрагмент большой директории, но при открытии файла сохранить полный путь до него. Для этого используется `root`.

Например, можно показать только содержимое `System/`:

````markdown
```files github="IgorShaposhnikov/Cvolo" ref="master" root="libraries/System"
System/
├── Console.cvl
└── Environment.cvl
```
````

В веб-интерфейсе документации читатель увидит компактное дерево:

```files github="IgorShaposhnikov/Cvolo" ref="master" root="libraries/System"
System/
├── Console.cvl
└── Environment.cvl
```

При этом клики по файлам по-прежнему открывают реальные пути `libraries/System/Console.cvl` и `libraries/System/Environment.cvl`.

Атрибут `root` не добавляет видимые строки в дерево. Он только дополняет путь, который используется при открытии файла.
