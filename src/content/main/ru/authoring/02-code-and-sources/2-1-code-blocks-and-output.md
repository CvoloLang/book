# 2.1 Блоки кода, ввод и вывод программы

Примеры кода — одна из главных частей технической документации. В Cvolo Docs они остаются обычными fenced-блоками Markdown, а сайт добавляет поверх них подсветку синтаксиса, название языка, кнопку Copy, опциональные номера строк и отдельное оформление ввода и вывода программы.

Для Cvolo используйте language id `cvolo`. Именно по нему рендерер выбирает грамматику подсветки Cvolo. Если указать `text`, содержимое останется моноширинным текстом без языковой подсветки.

## Обычный блок Cvolo

Для небольшого примера достаточно стандартного fence:

````markdown
```cvolo
val x = 5;
Console.WriteLine(x);
```
````

На сайте он будет выглядеть так:

```cvolo
val x = 5;
Console.WriteLine(x);
```

Подсветка Cvolo, подпись языка и кнопка Copy добавляются автоматически. Автору статьи не нужно добавлять подписи вроде `Code:` или вручную оформлять кнопку копирования.

Сам пример не должен заменять объяснение. Перед блоком или после него стоит коротко указать, что именно показывает код и на какую часть нужно обратить внимание.

Если пример относится не к Cvolo, укажите его настоящий язык — например `toml`, `json`, `html`, `text` или `markdown`.

## Номера строк

По умолчанию номера строк отключены. Для коротких примеров они обычно создают лишний визуальный шум, поэтому включать их стоит только тогда, когда текст статьи ссылается на конкретные строки или длинный пример действительно требует дополнительной навигации.

Чтобы включить номера, добавьте `lines` сразу после имени языка в открывающем fence:

````markdown
```cvolo lines
var counter = 0;
Console.WriteLine(counter);

counter = counter + 1;
Console.WriteLine(counter);
```
````

На сайте получится тот же код с номерами строк:

```cvolo lines
var counter = 0;
Console.WriteLine(counter);

counter = counter + 1;
Console.WriteLine(counter);
```

Номера добавляются только при отображении блока и не становятся частью исходного кода. Кнопка Copy также копирует код без номеров строк.

Поддерживаются формы `lines=true`, `line-numbers=true` и `linenumbers=true`, но для новых статей лучше использовать короткую форму `lines`.

Если номера нужно явно отключить, например в программно сгенерированном Markdown, можно использовать `lines=false`.

## Ввод и вывод программы

Для примеров с консольным взаимодействием можно добавить к блоку кода отдельные секции ввода и вывода. Они записываются обычными соседними fence-блоками, а рендерер объединяет их с кодом в один визуальный пример.

Используйте:

- `input` — для данных, которые программа получает через стандартный ввод;
- `output` — для данных, которые программа выводит в терминал.

Оба блока необязательны. Если программа ничего не читает, достаточно `output`. Если важно показать только вводимые данные, можно использовать один `input`.

### Только вывод

Если программа только печатает результат, сразу после блока кода добавьте `output`:

````markdown
```cvolo
Console.WriteLine("Hello, Cvolo!");
```

```output
Hello, Cvolo!
```
````

На сайте оба fence отображаются как один пример:

```cvolo
Console.WriteLine("Hello, Cvolo!");
```

```output
Hello, Cvolo!
```

`output` относится к блоку кода непосредственно перед ним. Поэтому между кодом и `output` не должно быть обычного текста или другого Markdown-блока.

### Ввод и вывод вместе

Если программа сначала получает данные от пользователя, а затем печатает результат, добавьте `input` перед `output`.

Например, программа читает имя из стандартного ввода и сразу выводит его обратно:

````markdown
```cvolo
val name = Console.ReadLine();
Console.WriteLine(name);
```

```input
Alice
```

```output
Alice
```
````

На сайте эти три fence становятся одним примером:

```cvolo
val name = Console.ReadLine();
Console.WriteLine(name);
```

```input
Alice
```

```output
Alice
```

Так читателю сразу видны три части одного запуска: какой код выполняется, какие данные передаются программе и какой результат она печатает.

Порядок блоков соответствует ходу выполнения программы:

```text
code → input → output
```

Если `input` или `output` не нужен, соответствующий блок просто опускается.

Например, допустимы обе формы:

```text
code → output
code → input
```

### Правила для блоков input и output

Блоки `input` и `output` должны идти непосредственно после блока кода и друг за другом. Не вставляйте между ними поясняющий абзац — иначе рендерер перестанет считать их частями одного примера.

Пояснение лучше размещать перед всей группой или после неё.

В `input` пишите только данные, которые действительно передаются программе через стандартный ввод. В `output` — только наблюдаемый результат выполнения. Не добавляйте туда комментарии автора, shell prompt или поясняющий текст.

Для `input` также поддерживается алиас `stdin`. Для `output` поддерживаются `stdout` и `result`. В новых статьях лучше использовать короткие формы `input` и `output`.
