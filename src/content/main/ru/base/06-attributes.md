# B6. Встроенные атрибуты

Base содержит декларации атрибутов, которые выглядят в исходном коде как обычные именованные сущности, но имеют compiler-known смысл. Они доступны без `using System;` и остаются частью Base в freestanding-сборке.

Атрибуты лучше читать по назначению: result/error shapes, оптимизация, безопасность, диагностика, enum/API evolution и native interop.

## B6.1 Result и Error

`[Result]` и `[Error]` связывают пользовательские типы с result-based control flow языка.

```cvolo
[Result]
union LoadResult<T, E> {
    T Ok;
    E Err;
}
```

`[Result]` не превращает произвольный тип в исключение. Он сообщает компилятору, что shape типа участвует в канонической модели успешного значения и ошибки.

`[Error]` используется для типов, которые описывают ошибочное состояние и могут участвовать в соответствующих проверках/diagnostics.

## B6.2 Политика оптимизации

К этой группе относятся `[Inline]`, `[NeverInline]` и `[Intrinsic]`.

```cvolo
[Inline]
int Add(int a, int b) {
    return a + b;
}
```

`[Inline]` и `[NeverInline]` задают policy/intent для оптимизатора. Они не меняют сигнатуру функции и не должны использоваться как замена корректной семантике программы.

`[Intrinsic]` помечает декларацию, реализация которой известна компилятору или backend и не обязана быть обычным пользовательским телом функции.

## B6.3 Безопасность и aliasing

В эту группу входят `[NoAlias]`, `[UnsafeBody]` и `[StrictMutability]`.

- `[NoAlias]` выражает дополнительный aliasing-контракт там, где это поддерживается сигнатурой.
- `[UnsafeBody]` разрешает unsafe-операции внутри тела, сохраняя явную границу небезопасного кода.
- `[StrictMutability]` усиливает правила мутабельности для отмеченного API/типа.

Эти атрибуты не отменяют borrow/lifetime правила языка; они уточняют контракт в местах, где компилятору нужна дополнительная информация.

## B6.4 Диагностика

Диагностические атрибуты помогают выражать намерение API.

- `[MustUse]` просит диагностировать проигнорированное значение, когда результат важен для корректности.
- `[SuppressWarning]` адресно подавляет предупреждение в месте, где автор сознательно принимает поведение.

Их назначение — сделать намерение исходного кода явным, а не отключить проверку программы целиком.

## B6.5 Enum и evolution API

`[Flags]` и `[NonExhaustive]` относятся к форме публичных типов и развитию API.

- `[Flags]` обозначает enum, значения которого предполагается комбинировать как битовые флаги.
- `[NonExhaustive]` сообщает, что публичный набор вариантов может расширяться и внешний код не должен полагаться на его окончательность.

## B6.6 Native interop

Interop-группа связывает исходный код Cvolo с внешними ABI и символами.

```cvolo
[LibraryImport("native")]
extern int NativeCall();
```

К этой группе относятся:

- `[LibraryImport]` — источник native-библиотеки;
- `[ImportName]` — внешнее имя импортируемого символа;
- `[ExposeName]` — имя, под которым Cvolo-символ экспортируется наружу.

Эти декларации лежат в Base, потому что FFI-контракт должен быть доступен независимо от hosted `System`.
